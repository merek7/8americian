Auto-hébergement

Tout ce qu'il faut savoir pour faire tourner ton propre serveur 8 American — version dédiée VPS, via Coolify, ou en local sur ton PC pour des parties LAN entre amis.

Vue d'ensemble

Le serveur 8 American est un binaire Godot tournant en mode --headless. Il écoute sur un port UDP (9080 par défaut), gère la logique de jeu, et relaie les actions des joueurs via le protocole ENet.

Pourquoi auto-héberger ?

  • Parties privées entre amis avec mot de passe
  • Maîtrise totale : ton serveur, tes règles, tes données
  • Pas de limite de temps ou de joueurs au-delà des 10 simultanés
  • Possibilité de modifier le code source pour expérimenter

Caractéristiques techniques

  • Empreinte : ~512 Mo RAM en idle, ~5% CPU sur 1 vCPU
  • Bande passante : < 1 Mo/heure pour 10 joueurs
  • Latence : ENet UDP, < 50 ms en local, 50-200 ms en intercontinental
  • Persistance : aucune (chaque crash redémarre le service propre)

Choisir sa méthode

Trois façons de faire selon ton besoin :

VPS Linux + systemd

Production stable

  • Auto-restart, logs centralisés
  • Démarrage au boot
  • Hardening sécurité complet
  • Idéal pour serveur public 24/7

Coolify

Déploiement managé

  • Interface web pour gérer
  • Update en 1 clic via Git
  • Pas de systemd à toucher
  • Idéal si tu connais Coolify

LAN local

Sans VPS

  • Aucun serveur distant requis
  • Tu héberges depuis ton PC
  • Idéal pour parties entre amis
  • Mise en place en 30 secondes

Méthode 1 — VPS Linux + systemd

Recommandé pour un serveur public 24/7 ou des parties privées Internet.

Pré-requis

  • VPS Linux x86_64 (Ubuntu 22.04+ ou Debian 12+ recommandé)
  • 1 vCPU, 512 Mo RAM minimum
  • Port UDP 9080 ouvert (UFW + firewall provider)
  • Accès SSH avec sudo

Étape 1 — Utilisateur dédié

⚠ Sécurité Ne fais jamais tourner le service en root. On crée un user système non-privilégié. 
sudo useradd -r -m -s /bin/bash jeucartes
sudo mkdir -p /opt/jeu-cartes
sudo chown -R jeucartes:jeucartes /opt/jeu-cartes

Étape 2 — Installer Godot

sudo apt update && sudo apt install -y wget unzip
cd /opt
sudo wget https://github.com/godotengine/godot/releases/download/4.6.2-stable/Godot_v4.6.2-stable_linux.x86_64.zip
sudo unzip Godot_v4.6.2-stable_linux.x86_64.zip
sudo mv Godot_v4.6.2-stable_linux.x86_64 godot
sudo chmod +x godot
sudo ln -sf /opt/godot /usr/local/bin/godot
godot --version

Étape 3 — Copier le projet

Télécharge l'archive serveur depuis la page d'accueil, puis depuis ton PC :

scp server-package.tar.gz user@TON_IP_VPS:/tmp/

Sur le VPS :

sudo tar -xzf /tmp/server-package.tar.gz -C /opt/jeu-cartes --strip-components=1
sudo chown -R jeucartes:jeucartes /opt/jeu-cartes

Étape 4 — Premier import

sudo -u jeucartes env HOME=/opt/jeu-cartes godot --headless \
  --path /opt/jeu-cartes --import

Étape 5 — Service systemd

Crée /etc/systemd/system/jeu-cartes.service :

[Unit]
Description=8 American — serveur dédié
After=network.target

[Service]
Type=simple
User=jeucartes
Group=jeucartes
WorkingDirectory=/opt/jeu-cartes
Environment=HOME=/opt/jeu-cartes
ExecStart=/usr/local/bin/godot --headless --path /opt/jeu-cartes -- \
  --server --port=9080 --start-on=2 --score=50 --password=CHANGE_MOI
Restart=always
RestartSec=5
NoNewPrivileges=true
ProtectSystem=strict
PrivateTmp=true
ReadWritePaths=/opt/jeu-cartes

[Install]
WantedBy=multi-user.target
🔐 Mot de passe Remplace CHANGE_MOI par un mot de passe fort. Génération : openssl rand -base64 16

Active et lance :

sudo systemctl daemon-reload
sudo systemctl enable --now jeu-cartes
sudo journalctl -u jeu-cartes -f

Étape 6 — Ouvrir le firewall

sudo ufw allow 9080/udp
sudo ufw reload

Côté provider (Hetzner Cloud Console / OVH / DigitalOcean), ouvre aussi UDP 9080 dans le firewall externe.

Étape 7 — Tester

Depuis le client Windows :

  1. Lance 8American_v1.01.beta.exe
  2. Menu → Multijoueur en ligne
  3. Onglet Rejoindre
  4. IP : ton IP VPS, Port : 9080, Mot de passe : celui défini
  5. Rejoindre

Méthode 2 — Coolify

Si tu utilises Coolify pour gérer tes services. Pas de Dockerfile officiel pour le serveur de jeu (Coolify est conçu pour HTTP), mais possible via un container générique.

ℹ Limitation Coolify gère bien les services HTTP/TCP mais pas naturellement les UDP exposés. Tu peux contourner en exposant le port UDP via Docker direct, ou rester sur la méthode VPS systemd (plus simple pour ce cas).

Approche Docker compose

Crée docker-compose.yml dans le repo serveur :

services:
  jeu-cartes:
    build: .
    image: 8american-server:latest
    restart: unless-stopped
    ports:
      - "9080:9080/udp"
    environment:
      - SERVER_PASSWORD=${SERVER_PASSWORD}
      - START_ON=2
      - SCORE_TARGET=50

Avec ce Dockerfile :

FROM debian:12-slim

RUN apt-get update && apt-get install -y wget unzip ca-certificates && \
    wget -q https://github.com/godotengine/godot/releases/download/4.6.2-stable/Godot_v4.6.2-stable_linux.x86_64.zip && \
    unzip -q Godot_v4.6.2-stable_linux.x86_64.zip && \
    mv Godot_v4.6.2-stable_linux.x86_64 /usr/local/bin/godot && \
    chmod +x /usr/local/bin/godot && \
    rm -rf *.zip /var/lib/apt/lists/*

WORKDIR /game
COPY game/ /game/

ENV HOME=/game
ENV SERVER_PASSWORD=""
ENV START_ON=2
ENV SCORE_TARGET=50

RUN godot --headless --path /game --import || true

EXPOSE 9080/udp

CMD godot --headless --path /game -- --server --port=9080 \
    --start-on=$START_ON --score=$SCORE_TARGET --password=$SERVER_PASSWORD

Dans Coolify :

  1. + New Resource → Docker Compose
  2. Source : repo Git public ou clone privé
  3. Variables d'environnement : ajoute SERVER_PASSWORD=ton-mdp
  4. Deploy

Vérifie que ton VPS expose bien UDP 9080 côté provider firewall (Coolify ne gère que les ports déclarés dans le compose).

Méthode 3 — LAN local (sans VPS)

Pour des parties entre amis sur le même réseau Wi-Fi/Ethernet — aucun serveur distant nécessaire.

Côté hôte (toi)

  1. Lance 8American_v1.01.beta.exe
  2. Menu → Multijoueur en ligne
  3. Pseudo + (optionnel) mot de passe dans le champ password
  4. Clique Héberger
  5. Note ton IP locale (ouvre une console : ipconfig sur Windows, cherche IPv4)

Côté invités

  1. Même version du jeu, même réseau Wi-Fi
  2. Multijoueur en ligne → Rejoindre
  3. IP : celle de l'hôte (ex. 192.168.1.42)
  4. Port : 9080
  5. Mot de passe si défini par l'hôte
⚠ Pare-feu Windows Au premier lancement de l'hôte, Windows demande l'autorisation. Coche Réseaux privés et clique Autoriser l'accès. Sinon, les invités ne pourront pas se connecter.

Quand le nombre requis de joueurs (par défaut 2) est connecté, l'hôte clique Démarrer la partie dans le lobby.

Référence CLI

Tous les flags supportés en mode dédié :

FlagDéfautDescription
--server—Active le mode dédié (obligatoire)
--port=N9080Port UDP d'écoute
--start-on=N2Démarre auto à N joueurs connectés
--score=N50Score cible (50 ou 100)
--password=XXX(aucun)Mot de passe requis pour rejoindre

Exemple complet :

godot --headless --path /opt/jeu-cartes -- \
  --server --port=9080 --start-on=4 --score=100 --password=PartieDuSamedi42

Sécurité — récap v1.01.beta

Le serveur dédié inclut plusieurs protections de base :

ProtectionDétail
Rate-limit30 RPC/sec/peer max, kick automatique si dépassé
Mot de passe--password=, kick si invalide
Pseudo plafonné32 caractères max, caractères de contrôle filtrés
Validationrequest_continue_round exige sender = joueur de la partie
User non-rootService systemd avec User=jeucartes
Hardening systemdNoNewPrivileges, ProtectSystem=strict, PrivateTmp

Limites connues

  • Trafic ENet non chiffré — un sniffer Wi-Fi voit les noms, scores et cartes en clair
  • Le mot de passe transite en clair dans le canal ENet (pas en JSON, mais lisible si interception MITM)
  • Pas de protection CAPTCHA / anti-bot — pour serveur public massif, ajouter un proxy applicatif
ℹ Pour usage privé entre amis Ces limites sont acceptables. Pour un serveur public exposé Internet 24/7, envisager d'ajouter DTLS (ENetMultiplayerPeer.set_dtls_*) dans une version future.

Mise à jour du serveur

Quand une nouvelle version sort :

# Sur ton PC
scp server-package.tar.gz root@VPS:/tmp/

# Sur le VPS
sudo systemctl stop jeu-cartes
sudo tar -xzf /tmp/server-package.tar.gz -C /opt/jeu-cartes --strip-components=1
sudo chown -R jeucartes:jeucartes /opt/jeu-cartes
sudo -u jeucartes env HOME=/opt/jeu-cartes godot --headless \
  --path /opt/jeu-cartes --import
sudo systemctl start jeu-cartes
sudo journalctl -u jeu-cartes -f

Pour Coolify : push sur le repo Git → Coolify auto-deploy (si activé) ou bouton Redeploy.

Dépannage

"Couldn't create an ENet host"

Le port est déjà occupé. Vérifie qu'aucune autre instance ne tourne :

sudo ss -ulnp | grep 9080
sudo systemctl stop jeu-cartes  # si le service tourne en parallèle

"Could not create directory: /home/jeucartes"

Tu as ProtectHome=true dans le service mais Godot veut écrire dans le home. Solution : pointe HOME vers le dossier projet en ajoutant Environment=HOME=/opt/jeu-cartes dans la section [Service], et retire ProtectHome=true.

Le client ne se connecte pas, rien dans les logs serveur

Le paquet n'atteint pas le serveur. Diagnostique dans cet ordre :

  1. sudo ufw status — la règle 9080/udp ALLOW doit être présente
  2. Firewall provider (Hetzner Cloud Console / OVH panel) — UDP 9080 doit être ouvert
  3. Test depuis ton PC : nc -uvz IP_VPS 9080 doit réussir

Le client se connecte mais est kické immédiatement

Mauvais mot de passe ou rate-limit dépassé. Logs serveur :

sudo journalctl -u jeu-cartes -n 50 | grep Kick

Le serveur crash en boucle au démarrage

Lance manuellement pour voir l'erreur sans systemd :

sudo -u jeucartes env HOME=/opt/jeu-cartes godot --headless \
  --path /opt/jeu-cartes -- --server --port=9080 --start-on=2 --score=50
